1. Таблица `wallets(id, balance bigint)` с одной строкой `balance = 1000`. Скрипт на Ruby/`pg` или `psql`, который из 10 параллельных соединений списывает по 200 через `SELECT balance … ; UPDATE … SET balance = balance - 200` с проверкой в приложении. Зафиксировать итоговый баланс (ожидается отрицательный).
2. Исправить тремя разными способами, каждый — отдельным скриптом: `SELECT … FOR UPDATE`; `CHECK (balance >= 0)` + обработка ошибки; уровень изоляции `SERIALIZABLE` с ретраем на `40001`.
3. Для каждого способа записать: итоговый баланс, сколько транзакций откатилось, время выполнения.
4. `EXPLAIN (ANALYZE, BUFFERS)` для запроса списка операций по кошельку за месяц на таблице в 1 млн строк — до и после добавления составного индекса `(wallet_id, created_at)`; записать оба плана.
5. Один partial index под запрос «неподтверждённые операции» и показать, что планировщик его использует.

Критерий: таблица результатов на 3 строки × 3 колонки в README и два плана с разницей хотя бы в 10 раз по `actual time`.
